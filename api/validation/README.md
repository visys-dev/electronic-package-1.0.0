# Результат перевірки контракту

Дата: 25.10.2026. Статус: пройдено. Контракт: OpenAPI 3.1.1, 33 операції. Перевірено openapi-spec-validator 0.7.2; приклади — jsonschema 4.26.0 з FormatChecker. Версії й SHA-256 контракту — result.json.

- Структура OpenAPI: помилок не виявлено.
- 11 позитивних прикладів: відповідають схемам.
- 8 негативних варіантів: відхилено за схемами.
- Усі US-01–US-10 мають операції; operationId унікальні.
- Арифметика контрольного прикладу: 120 хв; рівність цілі не є перевищенням.

Повторний запуск із кореня проєкту у середовищі з установленими залежностями:

```bash
python3 api/validation/validate_contract.py
```

У цій перевірці залежності встановлено лише в /tmp/coursework-openapi-validator, без змін системних пакетів, і запускали з PYTHONPATH, що вказує на цей каталог. Для відтворення в новому середовищі використовувати requirements.txt у віртуальному оточенні.

Це перевірка документа контракту та прикладів. Жоден TEST-01–TEST-39 не отримав статусу «пройдено». Авторизація, SQL-обмеження, конкуренція, транзакції, фонова доставка та NFR-04 на реалізації не перевірялися. Схеми не виражають усі міжпольові/міжзаписні правила: вони описані в api/README.md і data/invariants.md та потребують серверних перевірок. Успішна валідація не є доказом працездатності сервера.

## Уточнення 05.11.2026

`result.json` вище зберігає історичний стан від 25.10.2026. На момент первинної перевірки 2.3 OpenAPI мав два уточнені description (API-06/API-07), без зміни схем і маршрутів. Подальшу зміну парольних maxLength наведено нижче. Поточні часткові статичні перевірки, нова сума та обмеження — `docs/validation-2.3.json` і `docs/validation-2.3.md`. Повний OpenAPI-валідатор повторно не запускався; 11 прикладів і 8 негативних варіантів JSON Schema перевірено знову. Наявний скрипт містить фіксовану дату й перезаписує result.json: перед наступним повним запуском виправити датування та зберегти історичний результат.

## Після зміни максимуму пароля на 64 — 05.11.2026

Актуальний SHA-256 і результат — `api/validation/password-length-2026-11-05.json`. За прямим запитом користувача змінено maxLength двох полів: LoginRequest.password та UserCreate.initialPassword. Повторно пройшли 11 прикладів і 8 наявних негативних варіантів; додатково перевірено 8 граничних комбінацій (64/65, ASCII/Unicode, дві схеми). 64 допускається перевіркою довжини, 65 відхиляється. Повний OpenAPI-валідатор і сервер не запускалися. Попередні JSON-результати зберігають історичні суми.
