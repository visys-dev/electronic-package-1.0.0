# Додаток Е Склад електронного пакета, інструкція запуску прототипу та відомості про використання штучного інтелекту

## Е.1 Склад електронного пакета

Електронні матеріали охоплюють специфікації, редаговані моделі, код прототипу та докази перевірок. Версія електронного пакета — **1.0.0** від **08.11.2026**; версія прототипу — **0.1.0**. Шляхи наведено відносно кореня проєкту. Результати виконання зафіксовано протоколами від 06.11.2026.

Склад матеріалів розмежовує повні проєктні специфікації та реалізований обсяг. Вихідні файли моделей, контракт і код дають змогу перевірити наведені рішення; результати тестів стосуються лише зафіксованого в протоколах обсягу.

Не включаються `prototype/.env`, `prototype/.local/`, приватні ключі, резервні копії БД, Docker volumes, `.venv`, кеші, робочі журнали та службові дані середовища розроблення. Наявність `.env.example` не означає передавання паролів. Зафіксовані протоколи перевірок зберігаються окремо від робочих журналів застосунку.

## Е.2 Запуск і демонстрація

Порядок перевірено для Linux x86_64. Потрібні Docker Engine, Docker Compose, Python 3 та OpenSSL; початкове завантаження образів і залежностей потребує мережевого доступу. Команди виконуються з кореня проєкту:

```bash
python3 prototype/scripts/init_local.py
docker compose --project-directory prototype config --quiet
docker compose --project-directory prototype up -d --build --wait
docker compose --project-directory prototype ps
```

Ініціалізація створює окремий COMPOSE_PROJECT_NAME, локальні паролі й навчальні сертифікати, не встановлюючи довіру в ОС. Назва проєкту в .env забезпечує окремий volume БД; скрипт не змінює наявний .env. Перед відкриттям сторінки слід перевірити відбиток CA:

```bash
openssl x509 -in prototype/.local/tls/ca.crt -noout -subject -issuer -dates -fingerprint -sha256
```

Сертифікат `prototype/.local/tls/ca.crt` потрібно додати до довірених CA браузера або використовуваного ним сховища ОС, усвідомлюючи додавання довіри до навчального CA. Приватний ключ CA не імпортується й не передається. Перевірка TLS не вимикається. Сторінка доступна за **https://localhost:8443**; порт PostgreSQL на хості не публікується.

Логіни `requester`, `specialist` і `coordinator` використовуються для створення, опрацювання та закриття заявки. Паролі беруться локально з `prototype/.env`; у записку їх не переносять. Для різних ролей потрібні окремі профілі браузера. Сценарій у `demo-scenario.md` описує створення заявки, призначення спеціаліста, початок роботи, публічне рішення та підтвердження заявником. Очікуваний результат — стан «Закрита» зі збереженою історією; чужий заявник і користувач лише з адміністративною роллю не бачать заявки.

Повторна демонстрація створює нову заявку без очищення БД. Зупинка зберігає дані у volume:

```bash
docker compose --project-directory prototype down
```

Повторний `up` виконує міграцію й початкову ініціалізацію без видалення заявок. Зміна пароля в `.env` після першої ініціалізації не змінює пароль уже створеного користувача в БД. Інструкція програмних тестів і їх вплив на навчальне середовище наведені в `README.md`; інтеграційний набір не призначений для робочої БД.

## Е.3 Використання штучного інтелекту

Під час підготовки роботи застосовувався Codex для аналізу матеріалів, створення й редагування чернеток, формалізації вимог, підготовки моделей, специфікацій, коду прототипу, тестів і супровідних документів. 
Тему, технологічну основу та предметні обмеження уточнено під час підготовки роботи. Допомога ШІ охоплювала формулювання й реалізацію рішень, а не лише мовне редагування.
