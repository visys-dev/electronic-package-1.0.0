# Модель загроз

Редакція: 05.11.2026. Проєктна оцінка; частота атак та ефективність захисту не виміряні. Вебінтерфейс і API одного походження, один серверний застосунок, одна реляційна БД; без зовнішніх інтеграцій.

Активи: зміст заявок і коментарів, internal-нотатки, права та членства, credential_hash і токени сеансу, незмінна бізнес-історія, знімки цілей, ключі повтору, діагностичні журнали. Адміністративна роль застосунку відрізняється від привілеїв оператора ОС/БД.

Межі довіри: TB-01 — недовірений браузер → HTTPS/API; TB-02 — автентифікований запит → конкретна заявка/черга та її проєкція; TB-03 — застосунок → БД; TB-04 — предметні дані → діагностика/резервні копії/електронний пакет. Прихований UI не утворює межі безпеки.

| ID / межа | Сценарій та наслідок | Проєктний контрзахід | План перевірки / залишкове обмеження |
|---|---|---|---|
| TH-01 / TB-02 | Підміна ticketId, queueId, курсора чи notificationId розкриває чужі записи | Перевірка кожного об’єкта й актуальних дозволів; фільтр до пагінації та агрегування; 404 | TEST-04/18/21/39; UUID не вважається дозволом |
| TH-02 / TB-02 | Internal-нотатка потрапляє у history/DTO або до власника із суміщеними ролями | Публічна проєкція власника має пріоритет; без internal-текстів та подій; explicit DTO | TEST-10/21; виконати після реалізації нотаток |
| TH-03 / TB-01 | Викрадення/фіксація сеансу або використання старого cookie після деактивації | Новий випадковий токен після входу, digest у БД, HTTPS, cookie-параметри, TTL та відкликання | TEST-21/38/39; компрометація браузера лишається ризиком |
| TH-04 / TB-01 | Стороння сторінка виконує зміну від імені користувача | Точний Origin, X-CSRF-Token, JSON, SameSite; login перевіряє Origin | TEST-21; дві вкладки та відсутні заголовки включені |
| TH-05 / TB-01 | Текст заявки виконується як код у браузері | Лише текстове відображення, контекстне кодування; не використовувати innerHTML для вхідного тексту [33] | TEST-02/09/21 із синтетичним HTML/скрипт-маркером; це не виконана XSS-перевірка |
| TH-06 / TB-01/03 | Підміна owner/state/role або SQL-фрагмент у полі | Дозволений набір полів; additionalProperties=false; параметризовані запити; сервер сам задає owner/стан | TEST-02/20/21; перевірити параметризовані запити через SQLAlchemy/psycopg |
| TH-07 / TB-03 | Повтор/конкуренція залишає дубль або неповну історію | Idempotency-Key для створення; expectedVersion; транзакція; рішення одним запитом | TEST-12/23/34/35; решта команд не має загальної exactly-once гарантії |
| TH-08 / TB-04 | Тіло заявки, пароль чи токен розкривається через logs, помилку або пакет | Дозволений набір полів журналу; секрети й тіла виключені; синтетичні дані; контроль доступу до копій | TEST-22/28; очищення пакетів і backup перевіряється окремо |
| TH-09 / TB-01 | Перебір пароля та дорогі запити вичерпують ресурси | Обмеження спроб входу, довжин і limit=1–100; generic-відмова; timeout | TEST-21/24; стійкість до розподіленої атаки не доведена |

Рішення власного проєкту не приписуються OWASP як готова модель цієї системи. TH-03/04 деталізовано в `security/session-policy.md`; TH-02 — у `security/access-matrix.md`; TH-08 — у `security/pii-policy.md`. Статус усіх TEST-ID залишається «не виконано».
