## Паролі

Для нових навчальних облікових записів прийнято 15–64 кодових точок Unicode без автоматичного обрізання або зміни регістру; дозволено вставлення з менеджера паролів. Мінімум 15 — вибір для входу без MFA з урахуванням [32]. Вхід перевіряє до 64 символів, не відхиляючи чинний пароль лише за політикою створення. Схема UserCreate наразі задає структурний діапазон 1–64; мінімум 15 — додаткова серверна доменна перевірка з 422 VALIDATION_ERROR для initialPassword, як і інші правила поза JSON Schema.

Для credential_hash обрано Argon2id із початковими m=19456 KiB, t=2, p=1 [31], унікальною випадковою сіллю від підтримуваної бібліотеки та збереженням параметрів у закодованому хеші. Формат і параметри хешу перевірено локальним тестом; швидкодію й ресурсні межі ще належить перевірити; власний алгоритм не розробляти. Початкові паролі не зберігаються у fixtures чи репозиторії; передаються при ініціалізації тестового середовища через захищене налаштування. UI адміністрування, MFA, зміна/відновлення пароля не додаються до мінімального прототипу; реальна експлуатація потребуватиме окремого рішення щодо життєвого циклу credentials.

Для невідомого логіна, невірного пароля, неактивного user та тимчасового обмеження — однаковий 401 UNAUTHENTICATED без підтвердження існування облікового запису. Перевірка невідомого логіна використовує фіктивний Argon2id-хеш, щоб не створювати очевидної різниці шляхів; рівність часу не гарантується. Проєктний початковий ліміт — 10 невдалих спроб за 15 хв на нормалізований логін та 50 за 15 хв на адресу клієнта; після досягнення межі подальша перевірка пароля блокується до завершення вікна. Це параметри для майбутньої перевірки, не рекомендація OWASP із такими числами. Для одного серверного процесу лічильники обмеженого розміру можуть бути в пам’яті; перезапуск їх скидає, захист розподіленого розгортання не заявлено. Не довіряти довільному X-Forwarded-For; за проксі використовувати лише явно довірений вузол.

## Cookie, строк і відкликання

Після входу створюється новий непрозорий токен з 32 випадкових байтів криптографічного генератора; у sessions зберігається лише SHA-256 digest. Cookie support_session: Secure, HttpOnly, SameSite=Strict, Path=/, без Domain. Токен не передається в URL, JSON, localStorage чи журнал. Фіксований абсолютний TTL — 8 годин: expires_at=created_at+8h, без автоматичного продовження. Окремого idle-timeout у цьому зрізі не передбачено; 8 годин не називаються нормою OWASP або підтвердженим рівнем захисту. До реального розгортання оцінити потребу коротшого TTL/idle-timeout.

Кожен запит перевіряє expires_at, revoked_at, active та поточні дозволи. За now>=expires_at доступ відхиляється. DELETE /session встановлює revoked_at та очищає cookie; повторний запит із відкликаним токеном отримує 401. Деактивація user припиняє доступ без очікування TTL; вилучення ролі/членства застосовується до наступного запиту. Серверний контроль доповнюється Cache-Control: no-store для захищених відповідей.

## CSRF та походження

Сервер і браузер мають одне налаштоване HTTPS-походження. POST /session перевіряє точний Origin до автентифікації та приймає лише application/json. Для автентифікованих POST/PUT/DELETE обов’язкові X-CSRF-Token і точний Origin; відсутній Origin та Origin:null відхиляються. Довірене походження береться з конфігурації, а не з довільного Host або forwarded-заголовка. GET не виконує бізнес-змін. SameSite доповнює ці перевірки [30].

LOGIN повертає випадковий CSRF-токен з 32 байтів, digest зберігається в csrf_digest. API-ME видає новий токен і атомарно замінює digest: це визначена технічна ротація сеансу, не бізнес-зміна заявки. Відповідь no-store, читання стороннім походженням не дозволяється. У конкурентних вкладках остання ротація робить попередній токен непридатним; клієнт відновлює токен після CSRF_FAILED та просить повторно підтвердити дію. Не запускати API-ME перед кожною командою. Порівняння digest — бібліотечне, без раннього виходу за першим відмінним байтом.

Токени живуть у пам’яті сторінки; вихід/401 очищує їх і захищені чернетки. У локальному запуску потрібен довірений HTTPS; послаблення TLS чи вимкнення Secure не є штатним способом демонстрації.
