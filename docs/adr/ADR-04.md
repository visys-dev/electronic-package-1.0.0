# ADR-04. Технології навчального прототипу

Статус: погоджено користувачем 05.11.2026. Реалізацію та запуск не підтверджено.

## Контекст і підстава

Вимог кафедри до технологій, за повідомленням користувача, немає. Користувач запропонував Python із FastAPI, підтримав Docker і після обговорення PostgreSQL доручив зафіксувати рекомендований комплект. Рішення конкретизує ADR-01, не змінює предметні правила або мінімальний обсяг прототипу.

## Обраний комплект

| Частина | Вибір |
| --- | --- |
| Мова та серверний фреймворк | Python, FastAPI |
| СКБД | PostgreSQL |
| Доступ до даних | SQLAlchemy, psycopg |
| Міграції | Alembic |
| Вебінтерфейс | Jinja2, HTML/CSS, невеликий JavaScript для JSON API |
| Запуск | Docker Compose; власний образ застосунку й окрема БД зі сталим volume |
| Програмні перевірки | pytest |

## Причини та межі

Комплект обрано для реалізації наявного HTTP-контракту, реляційної моделі та наскрізного сценарію в одному серверному застосунку. Простий серверний вебінтерфейс відповідає поточному обсягу макетів. Docker Compose визначено способом відтворюваного запуску навчального середовища. Окремий frontend-фреймворк, брокер, Redis і Kubernetes не входять до рішення.

Серверні сеанси, CSRF, перевірки ролей/черг, ідемпотентність та транзакційні межі залишаються вимогами до реалізації. Вибір FastAPI не означає переходу на JWT або зміни контракту api/openapi.yaml. Автоматично сформований опис API потрібно буде звірити з чинним контрактом.

## Що ще потрібно визначити та перевірити

- Сумісні точні версії Python, PostgreSQL, пакетів та образів; зафіксувати залежності перед реалізацією.
- Фізичні типи, обмеження, індекси, рівень ізоляції, блокування, timeouts і повтори транзакцій.
- Бібліотеку Argon2id та перевірку її параметрів.
- ASGI-сервер, локальне HTTPS і довіру до сертифіката без послаблення чинних вимог до cookie.
- Міграції, синтетичну ініціалізацію, конфігурацію секретів, healthcheck і процедуру запуску. ОС демонстраційного хоста ще не уточнена.

Образи, compose-файл, міграції та програма цим документом не створюються. На дату прийняття 05.11.2026 TEST-01–TEST-39 залишалися невиконаними; поточні результати від 06.11.2026 — tests/results.md. Порівняльних вимірювань альтернатив не проводили; твердження про універсально найкращий стек не робиться.

## Вплив

Виконану синхронізацію матеріалів відображено в docs/stack-impact-review.md; точні заміни для Word — docs/word-stack-changes.md. Академічне обґрунтування вибору належить до 3.1; попередні підрозділи мають містити узгоджені короткі посилання на обрані технології без дублювання обґрунтування.
