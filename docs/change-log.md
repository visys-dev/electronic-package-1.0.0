
## 08.11.2026 — виправлення ізоляції Docker Compose

Під час запуску перенесеної копії migrate завершився помилкою автентифікації coursework_owner. Встановлено: стала назва Compose coursework-support повторно використала volume coursework-support_database від 06.11.2026, тоді як новий .env мав інші паролі. Скрипт init_local.py тепер генерує окремий COMPOSE_PROJECT_NAME для нової конфігурації; наявний .env не перезаписує. До .env запущеної копії додано окрему назву без зміни паролів. Старий volume не змінено й не видалено; у ньому залишаються 40 заявок. Нова копія використовує окрему БД.

Виправлено скрипт, .env.example і README у робочому проєкті та двох копіях пакета. Перевірено різні імена проєктів/volumes на двох тимчасових конфігураціях та збереження .env при повторі. Реальний запуск: migrate exit 0, app healthy, HTTPS health 200 і вхід requester 200 з перевіркою CA/hostname. Повний pytest і браузерні потоки повторно не виконано; TEST-статуси незмінні. Історичні контрольні суми 06.11.2026 не переписано: відрізняються лише скрипт початкової конфігурації й .env.example. Поточні суми пакета оновлено; протокол — docs/validation-compose-isolation.json у пакеті.
