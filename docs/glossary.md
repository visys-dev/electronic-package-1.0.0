# Робочий глосарій системи

Основні терміни проєкту

| Термін | Значення у проєкті |
|---|---|
| Заявка | Зареєстроване звернення з номером, описом, станом та історією опрацювання |
| Категорія | Ознака змісту звернення, за якою визначається напрям підтримки |
| Черга підтримки | Сукупність заявок певного напряму та визначене коло спеціалістів; фільтр є лише способом перегляду |
| Пріоритет | Ознака важливості опрацювання, з якою пов’язуються цільові строки |
| Перша відповідь | Перший публічний коментар спеціаліста або координатора до заявки |
| Вирішення та закриття | Фіксація запропонованого рішення та окреме завершення заявки після підтвердження заявником |
| Внутрішня нотатка | Повідомлення для уповноважених працівників підтримки, недоступне заявнику |
| Ескалація | Внутрішнє сповіщення координатору про порушення строку без автоматичної зміни виконавця чи пріоритету |

Джерело: робочі визначення відповідно до прийнятих меж системи.


Документ деталізує термінологію підрозділу 1.2; конкретні часові правила наведено в docs/requirements.md.

## Уточнення моделі даних та API (2.2)

| Позначення | Значення |
|---|---|
| ERD-01 | Логічна модель 16 сутностей; три узгоджені подання |
| low / normal / high / critical | Коди пріоритету; normal — «Звичайний» |
| version / expectedVersion | Поточна версія агрегату / версія, яку прочитав клієнт |
| Idempotency-Key | UUID повтору створення в контексті користувача; власна домовленість API |
| UTC/ms | Моменти UTC, тривалості у цілих мілісекундах; JSON RFC 3339 із Z |
| policy revision | Незмінна редакція конфігурації цілей; заявка зберігає її знімок |
