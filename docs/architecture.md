# Архітектура системи управління заявками

Редакція 06.11.2026. Проєкт; графічну модель ARCH-01 створено через Drawio MCP, базовий програмний сценарій перевірено, межі — docs/prototype-scope.md, докази — tests/results.md. Основний текст: report/06 Підрозділ 2.1.md. Рішення: docs/adr/ADR-01.md–ADR-04.md.

## Межі й залежності

Одна організація, чотири ролі, спільне походження вебінтерфейсу й API. Три фізичні учасники взаємодії: браузер, серверний процес і база даних. Серверний процес може одночасно виконувати HTTP-оброблення та фонові завдання; це один керований життєвий цикл застосунку. Зовнішні пошта, SSO, брокер повідомлень та хмарні сервіси не є базовими залежностями. За погодженим ADR-04 обрано Python/FastAPI, PostgreSQL і Docker Compose. C1 використовуватиме HTML/CSS/JavaScript зі сторінками Jinja2; C2–C4 — модулі Python у застосунку FastAPI; C5 — SQLAlchemy та psycopg. Міграції передбачено на Alembic, програмні перевірки — на pytest. Базовий зріз реалізації підтверджено; повний проєкт, зокрема C4/outbox, ще не реалізовано.

C1 — браузерний інтерфейс; C2 — прикладні сценарії; C3 — предметні правила заявок; C4 — часові розрахунки, події та сповіщення; C5 — адаптери збереження. C2 визначає транзакцію; C3 і C4 не відкривають незалежних транзакцій усередині тієї самої дії. Контракти сховища визначені з боку прикладного шару; реалізації C5 залежать від цих контрактів. C2–C4 не повинні залежати від конкретного драйвера бази. Діагностичне журналювання є технічною функцією, не користувацькою бізнес-історією D4.

## Дані та контроль

Браузер надсилає HTTPS-запит із даними й контекстом сесії. Сервер сам визначає користувача, актуальні ролі та черги. Значення ролі або власника в тілі запиту не вважаються доказом повноважень. Вхідні команди й вихідні представлення відокремлюються від внутрішніх записів. Усі зміни проходять перевірку стану й версії; читання також потребує авторизації. JSON використовується для прикладних запитів і відповідей, не для прямого обміну з базою.

Авторизоване створення: валідація → визначення категорії/черги/цілей → збереження заявки, історії й результату повторюваної операції → commit → відповідь. У повному проєкті в цю транзакцію входить відкладена подія. У мінімальному прототипі сповіщення не є обов’язковими; відсутність D6 не допускає втрати атомарності заявки та історії.

Публічне рішення разом зі зміною стану є однією транзакцією: запис повідомлення, стану, часових подій і історії. Перша відповідь фіксується лише за визначенням BR-07. Застаріла версія відхиляється, а не перезаписує прийняту зміну.

## Повтори, час і відмови

Ідентифікатор повтору унікальний у контексті користувача. Запис результату містить контрольний відбиток нормалізованого вмісту, а не секрети. Два одночасні однакові запити мають узгоджуватися обмеженням унікальності; переможець фіксує результат, другий отримує його після завершення першої транзакції або явну відповідь про тимчасовий конфлікт із можливістю повтору. Детальний контракт — 2.2. Зміна вмісту з тим самим ключем є конфліктом. Перед поверненням старого результату доступ перевіряється знову.

Час береться з серверного джерела UTC через замінюваний інтерфейс годинника. У тестах потрібен керований час, а не очікування годин. Перед паузою, вирішенням, першою відповіддю або допустимою зміною пріоритету обчислюються старі показники та фіксується вже наявне порушення. Фонове завдання перевіряє активні показники також без дій користувача. Після штатного перезапуску прострочення визначається за збереженими мітками; воно не залежить від безперервного перебування таймера в пам’яті. Затримка фонового завдання може затримати сповіщення, але не змінює формули показника. Продуктивність годинника й затримку сповіщень не вимірювали.

У повному проєкті оброблення D6 використовує унікальні ключі сповіщень та транзакцію «створити відсутні повідомлення + позначити подію обробленою». Повтори допускаються, дубль кінцевого сповіщення — ні. При збої незавершена транзакція відкочується; подія лишається доступною для повтору. Якщо застосунок зупинено, вебоперації й фонова обробка недоступні до запуску; безперервну доступність не заявлено. Перезапуск або резервне копіювання не замінюють перевірки відновлення.
