# Перевірка джерел підрозділу 1.3

Дата перевірки: 24.10.2026. Використано первинні офіційні сторінки. Збережено метадані, адреси, локатори та короткі доказові нотатки; повні архівні копії вебсторінок не зберігалися.

## SRC-022 / [17] IEEE Computer Society — SWEBOK Guide v4.0a

Джерело: [Guide to the Software Engineering Body of Knowledge, v4.0a](https://ieeecs-media.computer.org/media/education/swebok/swebok-v4.pdf). Редактор: Hironori Washizaki. На обкладинці перевірено позначення «Released August 2026»; рік copyright не підміняє дату випуску цієї редакції.

Місце перевірки: Chapter 1, Software Requirements; §3.1 Basic Requirements Analysis; друкована сторінка 1-8, сторінка PDF 50 за нумерацією від 1.

Підтверджено: для окремої вимоги описано однозначність, перевірюваність і відповідність потребам зацікавлених сторін; для сукупності — повноту, узгодженість і здійсненність з урахуванням ресурсних обмежень.

Застосування: перший абзац підрозділу 1.3. Конкретні числові цілі та кількість вимог цим посібником не встановлено. Це методична основа з програмної інженерії; відповідність усій книзі або обов’язковому стандарту не заявляється.

Обсяг перевірки: прочитано релевантний фрагмент офіційного PDF, отримано зображення відповідної сторінки. Повний посібник не аналізувався; локальну повну копію PDF не збережено. Збережено URL, редакцію, точний локатор і доказові нотатки.

## SRC-018 / [18] Cucumber — Reference (Gherkin)

Джерело: [Reference (Gherkin)](https://cucumber.io/docs/gherkin/reference/).

Місце перевірки: Given; When; Then.

Підтверджено: Given описує початковий контекст, When — подію, Then — очікуваний спостережуваний результат.

Межі використання: Використано форму опису; не заявлено встановлення Cucumber або виконання автоматизованих тестів.

## SRC-019 / [19] W3C — Web Content Accessibility Guidelines (WCAG) 2.2

Джерело: [Web Content Accessibility Guidelines (WCAG) 2.2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/).

Місце перевірки: 2.1.1 Keyboard; 2.1.2 No Keyboard Trap; 2.4.7 Focus Visible; 3.3.1 Error Identification.

Підтверджено: Вибрані критерії охоплюють клавіатуру, відсутність пастки, видимий фокус і текстове визначення помилок введення.

Межі використання: Чотири критерії не підтверджують повної відповідності WCAG A/AA. Збереження введених значень — додаткова вимога проєкту.

## SRC-020 / [20] OWASP Foundation — Logging Cheat Sheet

Джерело: [Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).

Місце перевірки: Event attributes; Data to exclude.

Підтверджено: Рекомендовано визначати атрибути подій та виключати з журналів секрети й чутливі дані.

Межі використання: Заборона записувати будь-які тіла заявок і коментарів, перелік полів та охоплення запитів визначені проєктом.

## Повторне використання [16]

[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) повторно перевірено: мінімальні привілеї, відмова за замовчуванням і серверна перевірка дозволів кожного запиту. Ролі, черги та права конкретного проєкту є авторськими рішеннями.

## Проєктні рішення та відсутні результати

Числа 150/4000/2000 символів, профіль 1000 заявок, 10 клієнтів, ціль p95 ≤ 2 с, правила станів і часових пауз задано як навчальні умови. Джерела не доводять їх оптимальності для конкретного підприємства. Приклади часу перевірено арифметично, але вони не є результатами виконання програми. 39 тестових випадків заплановано, жоден не виконано. Стек не обрано.

Для WCAG використано фіксовану редакцію Recommendation від 12.12.2024, а не робочу чернетку. Дати публікації інших вебсторінок не встановлювалися; дата звернення не підміняє дату видання.

## Заміна NASA за коментарем до підрозділу 1.3

24.10.2026 повторно перевірено [NASA, 4.2 Technical Requirements Definition](https://www.nasa.gov/reference/4-2-technical-requirements-definition/), §4.2.1.2.4. Джерело справді обґрунтовує перевірюваність, здійсненність і зв’язок технічних вимог з очікуваннями зацікавлених сторін. Проте звертатися саме до NASA для цього абзацу не потрібно: SWEBOK є ближчим до програмної інженерії джерелом. Формулювання уточнено з розмежуванням властивостей окремої вимоги та сукупності вимог.

SRC-017 збережено лише в історії метаданих; новий сталий ID — SRC-022. Бібліографічний номер [17] збережено; активних джерел залишається 20. Зміни внесено до Markdown. DOCX зберігає попередній абзац і має бути оновлений під час фінального експорту за погодженням користувача.
