# Перевірка джерел підрозділу 2.1

Дата: 24.10.2026. Збережено бібліографію, URL, місця перевірки та короткі нотатки. Повні копії вебсторінок і нормативного PDF не збережено.

## SRC-023 / [21] Visual Paradigm

Назва: What is Data Flow Diagram?.

Джерело: [What is Data Flow Diagram?](https://www.visual-paradigm.com/guide/data-flow-diagram/what-is-data-flow-diagram/).

Місце перевірки: DFD Symbols; Top-Down Decomposition Techniques; Balancing DFD; Context-Level Diagram.

Підтверджено: Потоки представляють дані; при декомпозиції зберігаються входи та виходи. Контекст представляє систему одним процесом.

Межі: Посібник інструмента, а не формальний стандарт. Для Gane–Sarson додатково звірено DFDs Symbols and Notations на офіційній сторінці https://online.visual-paradigm.com/resources/data-flow-diagram/guides/what-is-a-data-flow-diagram/. Нумерацію рівнів визначено методичкою курсової.

## SRC-024 / [22] Object Management Group

Назва: OMG Unified Modeling Language (OMG UML), Version 2.5.1.

Джерело: [OMG Unified Modeling Language (OMG UML), Version 2.5.1](https://www.omg.org/spec/UML/2.5.1/).

Місце перевірки: Normative Documents; Formal Versions.

Підтверджено: Офіційна картка надає нормативну специфікацію UML 2.5.1 та дату прийняття December 2017.

Межі: Картку та посилання перевірено; повний нормативний PDF не прочитано: засіб перегляду відхилив його через розмір 18 069 510 байтів. Використано для фіксації версії, не для заяви про повну відповідність моделей UML.

## SRC-025 / [23] Microsoft

Назва: Common web application architectures.

Джерело: [Common web application architectures](https://learn.microsoft.com/en-us/dotnet/architecture/modern-web-apps-azure/common-web-application-architectures).

Місце перевірки: What is a monolithic application?; What are layers?; Clean architecture.

Підтверджено: Описано одну одиницю розгортання, логічне розділення відповідальностей та залежності від контрактів прикладного ядра.

Межі: Приклади стосуються .NET/Azure; їх наявність не означає вибору цих продуктів. Конкретні модулі й вибір архітектури обґрунтовано вимогами навчального проєкту.

## SRC-026 / [24] Microsoft

Назва: Implement the Transactional Outbox pattern by using Azure Cosmos DB.

Джерело: [Implement the Transactional Outbox pattern by using Azure Cosmos DB](https://learn.microsoft.com/en-us/azure/architecture/databases/guide/transactional-out-box-cosmos).

Місце перевірки: Summary; Error handling.

Підтверджено: Стан бізнес-об’єкта та подія зберігаються разом; фонове оброблення допускає повтори, які потребують усунення дублів.

Межі: Використано принцип, не реалізацію Cosmos DB/change feed/Service Bus. Проєктна адаптація для внутрішніх сповіщень спільної бази потребує власних перевірок; гарантовану доставку за всіх відмов не заявлено.

## Проєктні рішення та обсяг доказів

Модульний моноліт, шість логічних сховищ, чотири процеси Level 0, модулі C1–C5 і спосіб оброблення внутрішніх сповіщень є рішеннями власного проєкту. Джерела не доводять досягнення p95 ≤ 2 с, безперервної доступності або повної відповідності нотації. Для цих висновків потрібні графічна й програмна перевірки.

Схеми DFD, UML і архітектури створено Drawio MCP та експортовано локальним редактором. Звірено контекст, напрямки, фактичні порти P2/P2.4 й вісім переходів; зображення переглянуто. Результати — docs/models/validation.md. Формальної сертифікації повної UML 2.5.1 або програмних тестів не виконано.

Робочі тексти зберігаються в Markdown за побажанням користувача. Версії СКБД, фреймворку й середовища ще не встановлено; використання Microsoft Learn не є рішенням обрати Azure або .NET. Дати випуску динамічних сторінок не вигадано. Посилання OMG використано лише для підтвердження версії UML 2.5.1 (прийняття December 2017).
